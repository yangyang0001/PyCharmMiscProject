## 1. `torch.nn` 与 `torch.nn.functional` 的关系

```python
import torch
import torch.nn as nn
import torch.nn.functional as F
```

这两个模块经常同时出现，容易搞不清各自负责什么，一句话区分：

- **`torch.nn`**：提供**带状态**的层，以类的形式存在（`nn.Conv2d`、`nn.Linear`……）。"带状态"指的是这些层内部自己持有可学习参数（权重 `weight`、偏置 `bias`），实例化一次，参数就被创建并跟着这个实例一直存在，可以反复调用、反复复用同一组参数。
- **`torch.nn.functional`**：提供**无状态**的纯函数版本（`F.relu`、`F.max_pool2d`……）。它们不持有任何参数，每次调用都要把输入（以及权重，如果需要的话）显式传进去，用完即走，不保留任何东西。

这也是为什么后面 `Net` 类里，`conv1`、`conv2`、`fc1`、`fc2`、`fc3` 都用 `nn.` 开头的类在 `__init__` 里创建（因为卷积核、全连接层的权重需要被记住、需要参与训练），而 `relu`、`max_pool2d` 用 `F.` 开头的函数在 `forward()` 里直接调用（因为它们没有任何需要学习的参数，纯粹是"对输入做一次固定的数学变换"）。

### 1.1 `relu` 和 `Linear` 的区别：激活函数 vs 全连接层

第2节 `forward()` 里几乎每一行都是 `F.relu(self.fcX(x))` 这种"先过 `Linear`、再过 `relu`"的组合，很容易把两者当成同一类东西混着理解。实际上它们处在完全不同的层次，职责也完全不同：

- **`nn.Linear`（全连接层）**：做的是**仿射变换** $y = xW^{\top} + b$（第11.2节有完整签名和权重 shape）。它是"层"，内部持有可学习参数 `weight`、`bias`，会被 `net.parameters()`（第5节）收集起来参与训练。数学上，这个变换是**线性**的——输入乘一个矩阵再加一个偏置。
- **`F.relu`（激活函数）**：做的是逐元素的 $\max(0, x)$（第11.3节）。它是"函数"，不持有任何参数，`net.parameters()` 里找不到它的任何痕迹。数学上，这个变换是**非线性**的——因为 `x<0` 和 `x≥0` 两段的行为不一样，图像在0处有一个"折角"，不是一条直线。

**为什么 `Linear` 后面几乎总要接一个 `relu`？** 因为**线性变换叠加线性变换，结果还是线性变换**——如果 `fc1`、`fc2`、`fc3` 中间不插入任何非线性的激活函数，无论堆多少层 `Linear`，数学上都能等价合并成一个"更大的" `Linear`（好比 $A(Bx)=({AB})x$，两次矩阵乘法可以合并成一次），网络的表达能力并不会因为"层数多"而变强。`relu` 插在两个 `Linear` 之间，就是故意打断这种"可合并性"，让网络具备拟合非线性、复杂模式的能力——这也是第4.1节③里"目的是给网络引入非线性，否则多层卷积叠加在数学上等价于一层卷积，学不到复杂模式"讲的同一个道理，只是那里针对卷积层，这里针对全连接层，本质完全一样。

**如果只用 `Linear`、不用任何激活函数会怎样？** 网络仍然能跑，`forward()` 也不会报错，但整个 `Net` 无论堆多少个 `nn.Linear`，效果都等价于一个单层的线性模型（更极端地说，就是最简单的线性回归/线性分类器），无法学到手写数字识别这种明显非线性的任务。反过来，如果只堆 `relu`、不用任何 `Linear`（没有可学习参数），网络里就没有任何东西能在训练中被更新，`loss.backward()` 也就无从谈起——两者缺一不可，**`Linear` 提供"可学习的线性组合能力"，`relu` 提供"打破线性、让网络能拟合复杂函数的非线性能力"**，分工完全不同。

| | `nn.Linear` | `F.relu` |
|---|---|---|
| 类型 | 层（`nn.` 类，有状态） | 函数（`F.` 函数，无状态） |
| 是否有可学习参数 | 有：`weight`、`bias` | 无 |
| 是否被 `net.parameters()` 收集 | 是 | 否 |
| 数学性质 | 线性（仿射变换 $y=xW^{\top}+b$） | 非线性（分段函数，负半轴截断为0） |
| 输出 shape 相对输入的变化 | 最后一维从 `in_features` 变成 `out_features`（第11.2节） | 与输入完全相同，只改变数值，不改变 shape（第11.3节） |
| 在网络中的角色 | 学习"怎么线性组合上一层的特征" | 决定"要不要让这个信号继续往后传"，并让多层网络不退化成单层 |
| 堆叠多个会怎样 | 多个 `Linear` 直接堆叠，等价于一个更大的 `Linear`（可合并） | 多个 `relu` 之间如果没有 `Linear`/`Conv` 夹在中间，本身不产生新的可学习能力 |

**一句话总结**：`nn.Linear` 是"权重"，`relu` 是"开关"——前者负责把上一层的特征做线性组合并产生新的特征，后者负责给这个组合结果加上非线性、决定信号是否/如何继续往后传递；两者交替出现（`Linear → relu → Linear → relu → ...`），才是神经网络能拟合复杂函数的关键，单独堆叠任何一种都不够。

### 1.2 仿射变换与线性归一化的区别：`nn.Linear` vs `transforms.Normalize`

上面反复提到 `nn.Linear` 做的是**仿射变换** $y = xW^{\top} + b$；数据预处理阶段常见的 `transforms.Normalize(mean, std)` 做的是**线性归一化**，两者形式上都是"乘一个数再加一个数"，很容易被当成同一回事，实际上是两个不同层面的东西：

| | 仿射变换（`nn.Linear`） | 线性归一化（`transforms.Normalize`） |
|---|---|---|
| 公式 | $y = xW^{\top} + b$，`W` 是矩阵 | $y = (x - \text{mean}) / \text{std}$，逐元素的标量缩放平移 |
| 维度间关系 | **可以混合不同维度**——输出的每一个分量都是输入所有分量的加权组合 | **各维度（各通道）互不影响**，每个通道独立减自己的 mean、除自己的 std |
| 参数怎么来 | `weight`、`bias` 是**可学习参数**，靠 `loss.backward()` + `optimizer.step()`（第8、9节）训练出来的 | `mean`、`std` 是**训练前人工算好或指定好**的统计量（比如 ImageNet 常用的 `[0.485, 0.456, 0.406]`），训练过程中固定不变 |
| 是否改变维度 | 可以改变（比如 `fc1 = nn.Linear(400, 120)` 把400维压成120维） | 不改变，输入输出 shape 完全一样 |
| 在网络里的角色 | 网络内部的"层"，是**模型的一部分**，参与前向计算图和反向传播 | 数据进网络之前的"预处理步骤"，**不属于模型**，也不参与训练 |

**换句话说**：线性归一化可以看作仿射变换的一个特例——如果把 `W` 限制成对角矩阵（即"每个输出分量只依赖对应的那一个输入分量，不和别的分量混合"），且 `W`、`b` 不是学出来的、而是由数据的统计量直接算出来的，仿射变换就退化成了线性归一化。两者的本质区别不在公式形式，而在于：**仿射变换会混合、学习特征之间的关系**，**线性归一化只是让数值落在一个更适合训练的范围里，不改变特征之间的相对关系**。

### 1.3 `relu` 是不是池化函数？——激活函数 vs 池化，两种完全不同的操作

第2节 `forward()` 里 `relu` 和池化（`max_pool2d`）经常紧挨着出现（`conv → relu → 池化`），容易被当成同一类东西，实际上两者职责毫无重叠：

| | `relu`（激活函数） | 池化（`max_pool2d` 等） |
|---|---|---|
| 作用对象 | **每个元素单独处理**，不看邻居 | **一个窗口内的多个元素一起处理**，取窗口内的统计量（最大值/平均值） |
| 输出 shape | 和输入**完全相同**，不做下采样 | 输出比输入**变小**（比如 `2×2` 窗口、`stride=2` 会让 H、W 各减半，见第4.2节公式） |
| 计算规则 | 逐元素 $\max(0, x)$，只看这一个数自己的正负 | 逐窗口取最大值/平均值，需要看一片区域 |
| 目的 | 引入**非线性**，让网络能拟合复杂函数（见第1.1节、第4.1节③） | **下采样、减少计算量**，同时让特征对微小位移更鲁棒（像素挪一点，池化结果大概率不变） |
| 是否有可学习参数 | 没有 | 没有（两者都是无状态的纯函数，这一点相同） |

```python
x = torch.tensor([[-1.0, 2.0], [3.0, -4.0]])

F.relu(x)
# tensor([[0., 2.],
#         [3., 0.]])          # shape 不变，仍是 2x2，只是负数变0

F.max_pool2d(x.unsqueeze(0).unsqueeze(0), 2)
# tensor([[[[3.]]]])           # shape 从 2x2 变成 1x1，取了窗口内的最大值
```

`relu` 回答的是"这个数要不要保留"（逐点判断），池化回答的是"这一片区域该用哪个数代表"（区域压缩）——两者是完全不同的操作，只是常常在 `forward()` 里前后相邻出现（第2节 LeNet-5 例子：`conv → relu → 池化`），并不存在"谁是谁的一种"这种从属关系。

## 2. 定义网络：以 LeNet-5 为例逐层拆解

### 2.0 定义网络这块，需要程序员参与的有哪些

在看具体代码之前，先分清楚"定义网络"这件事里，哪些是**程序员必须做的设计决策**，哪些是 **PyTorch 自动帮你搞定的事情**——理清这条界线，才知道自己接下来在写的每一行代码，到底是在做什么。

**需要程序员参与的：**

1. **继承 `nn.Module` 并调用 `super().__init__()`**——格式上的硬性要求，但具体继承哪个类、要不要多继承是程序员的选择。
2. **选择用哪些层、每层的超参数**——用几层卷积、几层全连接，每层的 `in_channels`/`out_channels`/`kernel_size`（第11.1节）、`in_features`/`out_features`（第11.2节）。这些数字直接决定网络的表达能力和参数量，没有"自动推荐"，需要根据任务（图像分类？回归？）和经验去设计。
3. **手工计算尺寸，保证层与层之间维度对齐**——比如 `fc1 = nn.Linear(16*5*5, 120)` 里的 `400`，必须顺着卷积/池化公式推一遍（第4节），算错了 `forward()` 跑到那一行就会直接报形状不匹配的错。
4. **编写 `forward()`，决定数据的流动顺序**——先卷积还是先池化、在哪里插入激活函数、要不要跳跃连接（残差）——这是在设计"计算流程图"，PyTorch 不会替你决定。
5. **选择激活函数的种类和插入位置**——`relu`、`sigmoid`、`tanh`……用哪种、插在哪几层之间，是设计决策（第1.1节讲过为什么需要它，但用哪种要人来定）。
6. **（训练阶段，非定义阶段）选择损失函数和优化器**——`nn.MSELoss` 还是 `nn.CrossEntropyLoss`，`SGD` 还是 `Adam`，虽然不属于"定义网络结构"本身，但也是围绕这个网络要做的人工决策（第7、9节）。

**不需要程序员参与、PyTorch 自动完成的：**

- **反向传播（`backward()`）**——完全不用写，autograd 引擎在 `forward()` 执行时自动建图，`loss.backward()` 自动沿图求梯度（本节下文、第8节）。
- **参数注册**——`self.conv1 = nn.Conv2d(...)` 这行赋值会被 `nn.Module` 重写过的 `__setattr__` 自动收进簿记字典，`net.parameters()` 能自动找到它们，不用手动维护参数列表（本节下文、第5节）。
- **权重的默认初始化**——每一层的 `weight`/`bias` 创建时会被自动随机初始化（合理的默认策略），不用自己写初始化代码，除非有特殊需求要自定义。

**一句话总结**：程序员要负责"网络长什么样、数据怎么流"这两件设计层面的事（选层、配参数、算尺寸、编排 `forward`），PyTorch 负责"底层怎么算梯度、怎么记账"这些工程层面的事。下面用 LeNet-5 逐层拆解，正是"选层、配参数、编排 `forward`"这几步具体怎么落地的完整示例。

先看完整代码（这是经典的 LeNet-5 结构，早期用于手写数字识别）：

```python
class Net(nn.Module):

    def __init__(self):
        super(Net, self).__init__()
        # 1个输入通道，6个输出通道，5x5的卷积核
        self.conv1 = nn.Conv2d(1, 6, 5)
        self.conv2 = nn.Conv2d(6, 16, 5)
        # 仿射变换：y = Wx + b
        self.fc1 = nn.Linear(16 * 5 * 5, 120)  # 16*5*5 来自图像尺寸的推导，见第4节
        self.fc2 = nn.Linear(120, 84)
        self.fc3 = nn.Linear(84, 10)

    def forward(self, input):
        # C1：卷积层，输出 6 张 28x28 的特征图，经过 relu 激活
        c1 = F.relu(self.conv1(input))
        # S2：池化层（下采样），2x2 窗口，输出 6 张 14x14 的特征图
        s2 = F.max_pool2d(c1, (2, 2))
        # C3：卷积层，输出 16 张 10x10 的特征图，经过 relu 激活
        c3 = F.relu(self.conv2(s2))
        # S4：池化层，输出 16 张 5x5 的特征图
        s4 = F.max_pool2d(c3, 2)
        # 展平成一维向量，保留 batch 维度（第6节详述）
        s4 = torch.flatten(s4, 1)
        # F5：全连接层 + relu
        f5 = F.relu(self.fc1(s4))
        # F6：全连接层 + relu
        f6 = F.relu(self.fc2(f5))
        # 输出层：10个类别的原始分数（不加 softmax，通常交给损失函数处理）
        output = self.fc3(f6)
        return output


net = Net()
print(net)
```

```
Net(
  (conv1): Conv2d(1, 6, kernel_size=(5, 5), stride=(1, 1))
  (conv2): Conv2d(6, 16, kernel_size=(5, 5), stride=(1, 1))
  (fc1): Linear(in_features=400, out_features=120, bias=True)
  (fc2): Linear(in_features=120, out_features=84, bias=True)
  (fc3): Linear(in_features=84, out_features=10, bias=True)
)
```

**几个关键点：**

- **必须继承 `nn.Module`，并且 `__init__` 里第一行必须调用 `super().__init__()`。** 这一步不是形式主义——`nn.Module.__init__()` 内部会初始化一系列"隐藏"的簿记字典（比如 `_parameters`、`_modules`），后面 `self.conv1 = nn.Conv2d(...)` 这行代码之所以能被自动注册进网络（进而被 `net.parameters()` 找到，见第5节），靠的正是 `nn.Module` 重写过的 `__setattr__`：只要赋值的对象是 `nn.Parameter` 或 `nn.Module` 的实例，就会被自动塞进对应的簿记字典里。如果跳过 `super().__init__()`，这套簿记机制不存在，后续赋值不会被注册，网络实质上是"空"的。
- **只需要写 `forward()`，不需要手写 `backward()`。** 这正是第1节 [02_自动微分.md](./02_自动微分.md#4-计算图是怎么建立的grad_fn-链条) 里讲的 autograd 引擎在起作用：`forward()` 里的每一步运算（卷积、relu、池化、全连接……）都是普通的张量运算，PyTorch 在执行 `forward()` 的过程中就已经把计算图悄悄建好了，之后调用 `loss.backward()`，反向传播是自动沿着这张图完成的，不需要人工在 `Net` 类里再写一个对称的反向函数。
- **调用网络实例时写 `net(input)`，而不是 `net.forward(input)`。** 两者效果目前看起来一样，但 `net(input)` 实际调用的是 `nn.Module.__call__`，它在真正执行 `forward()` 前后还会触发注册过的 hook（比如调试、监控用的 forward hook），直接调 `net.forward(input)` 会跳过这些机制——**永远用 `net(input)` 这种调用方式，不要直接调 `.forward()`**。

### 2.1 官方教程原版写法：逐行拆解 `forward` 与 `num_flat_features`

PyTorch 官方教程（以及很多教材）里这个例子写的是下面这个版本，和上面略有出入——**两者是同一个网络，只是 `forward` 里的写法风格、展平（flatten）的实现方式不一样**，这里逐行讲清楚区别：

```python
import torch
import torch.nn as nn
import torch.nn.functional as F


class Net(nn.Module):

    def __init__(self):
        super(Net, self).__init__()
        # 1 input image channel, 6 output channels, 5x5 square convolution
        # kernel
        self.conv1 = nn.Conv2d(1, 6, 5)
        self.conv2 = nn.Conv2d(6, 16, 5)
        # an affine operation: y = Wx + b
        self.fc1 = nn.Linear(16 * 5 * 5, 120)
        self.fc2 = nn.Linear(120, 84)
        self.fc3 = nn.Linear(84, 10)

    def forward(self, x):
        # Max pooling over a (2, 2) window
        x = F.max_pool2d(F.relu(self.conv1(x)), (2, 2))
        # If the size is a square you can only specify a single number
        x = F.max_pool2d(F.relu(self.conv2(x)), 2)
        x = x.view(-1, self.num_flat_features(x))
        x = F.relu(self.fc1(x))
        x = F.relu(self.fc2(x))
        x = self.fc3(x)
        return x

    def num_flat_features(self, x):
        size = x.size()[1:]  # all dimensions except the batch dimension
        num_features = 1
        for s in size:
            num_features *= s
        return num_features


net = Net()
print(net)
```

**逐段解释每一部分在干什么、为什么这么写：**

- **`class Net(nn.Module):` / `def __init__(self): super(Net, self).__init__()`**：和第2节完全一样——继承 `nn.Module`，先调用父类构造函数，把网络注册机制打开。`super(Net, self).__init__()` 和更简洁的 `super().__init__()` 是完全等价的写法，前者是 Python 2/3 通用的"显式传类名+实例"写法，后者是 Python 3 专属的简写，教程里用的是前者只是历史遗留习惯，不影响任何行为。
- **`self.conv1 = nn.Conv2d(1, 6, 5)` 等五行**：定义五个带参数的层，和第2节一模一样，含义见第2节和第4节的尺寸推导表格。
- **`def forward(self, x):` 里反复写 `x = ...(x)`，而不是像第2节那样每层起一个新名字（`c1`、`s2`、`c3`、`s4`……）**：这是两种同样常见的编码风格，效果完全一致——**把每一步的结果重新赋值回同一个变量名 `x`**，好处是不用为每一层单独想名字，写起来更快；坏处是调试时如果想在中间某一步打断点看某层的输出，不如"一层一个变量名"直观。两种写法生成的计算图、算出来的数值**完全相同**，纯粹是代码风格上的取舍。
- **`x = F.max_pool2d(F.relu(self.conv1(x)), (2, 2))`**：把"卷积 → relu → 池化"三步压缩成了一行嵌套调用，从内到外读：`self.conv1(x)` 先做卷积，`F.relu(...)` 再对卷积结果做激活，`F.max_pool2d(..., (2, 2))` 最后对激活结果做 `2×2` 窗口的最大池化。和第2节里分成 `c1 = F.relu(...)` 再 `s2 = F.max_pool2d(c1, ...)` 两行相比，只是**把两行合并成了一行**，本质操作完全一样。
- **注释 `# If the size is a square you can only specify a single number`，对应第二次池化 `F.max_pool2d(F.relu(self.conv2(x)), 2)`**：这里池化窗口只传了一个数字 `2`，不是 `(2, 2)` 这样的元组——PyTorch 里凡是需要"窗口大小"、"卷积核大小"这类参数的地方，**如果高和宽相等（正方形窗口），可以只传一个整数，PyTorch 会自动把它理解成 `(2, 2)`**；如果高和宽不相等（比如想要 `2×3` 的窗口），才必须写成完整的元组 `(2, 3)`。这行注释就是在提醒："这里传单个数字 `2`，是因为窗口是正方形，不是因为可以偷懒少写"。
- **`x = x.view(-1, self.num_flat_features(x))`，配合下面的 `num_flat_features` 方法**：这是这版代码和第2节版本**唯一的实质区别**——都是"把多维特征图展平成二维 `[batch, 特征数]`"，只是实现方式不同：
  - 第2节用的是 `torch.flatten(s4, 1)`：直接调用现成的展平函数，`1` 表示"从第1维开始展平"（第0维是 batch，保留不动）。
  - 这里用的是 `x.view(-1, self.num_flat_features(x))`：`.view()` 是更底层的"重新解释张量形状"操作，需要**手动算出**"除了 batch 维之外，每个样本一共有多少个数"，也就是 `num_flat_features(x)` 这个辅助方法在做的事；第一个参数 `-1` 是"占位符"，告诉 PyTorch"这一维的大小你帮我自动算，我只告诉你第二维应该是多少"——由于总元素个数是固定的，PyTorch 能反推出 `-1` 这一维应该等于 batch size。
  - **`num_flat_features` 方法逐行看**：`size = x.size()[1:]` 拿到 `x` 的形状、但**跳过第0维**（`[1:]` 是切片，去掉第一个元素），因为第0维是 batch size，展平时不能把它也算进"每个样本的特征数"里；接着 `num_features = 1` 起个乘积累加器，`for s in size: num_features *= s` 把剩下几个维度的大小依次乘起来——如果 `x.shape == [1, 16, 5, 5]`，`size` 就是 `(16, 5, 5)`，循环算出 `16×5×5=400`，和第4节表格里手推的结果完全一致。
  - **这两种写法（`torch.flatten` vs `view`+`num_flat_features`）算出来的张量在数值和 shape 上完全相同**，`torch.flatten` 是后来 PyTorch 版本加入的"语法糖"，把 `num_flat_features` 这段手动算元素个数的逻辑封装掉了；教程里保留手写版本，是为了让初学者看清楚"展平"这一步到底在做什么运算，而不是直接调一个黑盒函数。**实际写代码时，两种都可以，`torch.flatten` 更简洁，是更推荐的现代写法。**
- **`net = Net()` / `print(net)`**：和第3.2节一样，创建网络实例并打印结构，用来检查每一层的参数配置是否符合预期。

**`net(input)` 这一步就是"使用网络做一次推理/预测"**：数据从 `input` 出发，依次流过 `conv1 → relu → 池化 → conv2 → relu → 池化 → flatten → fc1 → relu → fc2 → relu → fc3`，最后吐出10个数字——LeNet-5 原本设计给手写数字识别用，10个数字对应"数字0~9各自的可能性打分"，数值越大代表网络认为越像那个数字（这里权重还是随机初始化的，没有训练过，所以打分没有实际意义，只是形状和流程是对的）。

```
输入    [1, 1, 32, 32]   4维：batch, channel, H, W
c1      [1, 6, 28, 28]
s2      [1, 6, 14, 14]
c3      [1, 16, 10, 10]
s4      [1, 16, 5, 5]
flatten [1, 400]         拍平成2维：batch, features
f5      [1, 120]
f6      [1, 84]
output  [1, 10]          仍是2维：batch=1, 10个类别的分数
```

**batch 维（第0维的 `1`）从头到尾都没被去掉。** 虽然这次只造了 1 张图（`torch.randn(1, 1, 32, 32)` 里第一个 `1` 就是 batch=1），但 PyTorch 不会因为 batch size 是 1 就自动把这一维"压掉"变成一维张量——它始终保留"这是一批数据里的第几张"这个维度，方便以后一次喂多张图（比如换成 `torch.randn(32, 1, 32, 32)`，跑出来 `out` 就是 `[32, 10]`）。所以 `out` 是二维：第0维是 batch，第1维是 `fc3` 算出的 10 个类别原始分数（logits）。

```python
# 完整最小示例：创建网络 -> 造输入 -> 使用网络 -> 看输出，四步缺一不可
import torch
import torch.nn as nn
import torch.nn.functional as F


class Net(nn.Module):
    def __init__(self):
        super(Net, self).__init__()
        self.conv1 = nn.Conv2d(1, 6, 5)
        self.conv2 = nn.Conv2d(6, 16, 5)
        self.fc1 = nn.Linear(16 * 5 * 5, 120)
        self.fc2 = nn.Linear(120, 84)
        self.fc3 = nn.Linear(84, 10)

    def forward(self, input):
        c1 = F.relu(self.conv1(input))
        s2 = F.max_pool2d(c1, (2, 2))
        c3 = F.relu(self.conv2(s2))
        s4 = F.max_pool2d(c3, 2)
        s4 = torch.flatten(s4, 1)
        f5 = F.relu(self.fc1(s4))
        f6 = F.relu(self.fc2(f5))
        output = self.fc3(f6)
        return output


net = Net()                          # ① 创建网络
input = torch.randn(1, 1, 32, 32)     # ② 造一个假输入
out = net(input)                       # ③ 使用网络（前向传播）
print(out)                             # ④ 看输出
```

后面第7~10节讲的"算损失、反向传播、更新参数"，都是在这四步的基础上继续往下接，并不是另起炉灶——先把这四步跑顺，后面的内容才有落脚点。

## 4. 卷积层与池化层的输出尺寸怎么算

`self.fc1 = nn.Linear(16 * 5 * 5, 120)` 里的 `16 * 5 * 5 = 400` 是怎么来的？这是新手最容易卡住的一步——**全连接层的输入维度，必须和上一层展平后的元素个数精确匹配**，而卷积、池化每一步都会改变特征图的空间尺寸（`H`、`W`），需要手工推一遍。

### 4.1 拆解 C1 层：`c1 = F.relu(self.conv1(input))` 里"6 张 28×28 特征图"是怎么来的

第2节代码里 `forward()` 第一行的注释——"C1：卷积层，输出 6 张 28x28 的特征图，经过 relu 激活"——包含两个完全不同来源的数字，**"6 张"和"28×28"要分开算**，混在一起想容易卡住：

**① "6 张"——直接来自 `out_channels`，不是算出来的**

`self.conv1 = nn.Conv2d(1, 6, 5)` 的三个参数是 `Conv2d(in_channels, out_channels, kernel_size)`：

- `in_channels=1`：输入通道数（灰度图只有1个通道）
- `out_channels=6`：**用6个不同的、各自独立可学习的 5×5 卷积核**去扫描同一张输入图，每个核学习捕捉一种不同的局部特征（边缘、纹理方向等）
- `kernel_size=5`：每个核大小 5×5

6个核各自卷积一遍，各输出一张特征图，6个核 → 6张特征图。**这个"6"是网络设计者设定的超参数**（对应第11.1节表格里的 `out_channels`），不是由输入尺寸推导出来的，改成8、16都可以，只是网络结构会变。

**② "28×28"——由输入尺寸和卷积核尺寸的滑动窗口计算算出来的**

输入是 `input = torch.randn(1, 1, 32, 32)`，即 32×32。一个 5×5 的窗口在 32×32 图上滑动（默认 `stride=1`、`padding=0`），横向能放的起始位置数是：

$$32 - 5 + 1 = 28$$

直观理解：核最左边占位置1~5，最右边占位置28~32，中间一共能滑动28个位置；纵向同理也是28。这正是下面4.2节通用公式 $\text{out}=\text{in}-\text{kernel\_size}+1$ 的具体代入，**每一个核（不管有几个）输出的空间尺寸都是这同一个28×28**，因为6个核用的是同一套滑动规则、同一个输入尺寸，只是各自学到的权重数值不同。

**③ "经过 relu 激活"——对这6张28×28的图逐元素做 `max(0, x)`**

`F.relu(...)` 把卷积结果里所有负值置0、正值不变，不改变shape（还是 `[1, 6, 28, 28]`），只改变数值——目的是给网络引入非线性，否则多层卷积叠加在数学上等价于一层卷积，学不到复杂模式。

**合起来**：`self.conv1(input)` 用6个独立的5×5卷积核对32×32输入各卷一遍，得到 `[1, 6, 28, 28]`（6是`out_channels`指定的核数，28×28是`32-5+1`算出的滑动窗口尺寸），`F.relu(...)` 再对这个结果逐元素做非线性变换，shape不变。

### 4.2 通用公式

**卷积层**（不加 padding，`stride=1` 时的简化版）：

$$\text{out} = \text{in} - \text{kernel\_size} + 1$$

**完整公式**（含 padding、stride、dilation，`dilation` 默认为1时可忽略）：

$$\text{out} = \left\lfloor \frac{\text{in} + 2\times\text{padding} - \text{kernel\_size}}{\text{stride}} \right\rfloor + 1$$

**池化层**（`kernel_size=2, stride=2`，最常见的配置）：

$$\text{out} = \left\lfloor \frac{\text{in}}{2} \right\rfloor$$

### 4.3 逐层验算（假设输入是 `32×32` 的单通道图像）

LeNet-5 的经典设计就是配合 `32×32` 输入尺寸推出来的，`forward()` 里每一步的 shape 变化如下：

| 步骤 | 操作 | 计算 | 输出 shape（`[N, C, H, W]`） |
|---|---|---|---|
| 输入 | — | — | `[1, 1, 32, 32]` |
| C1 | `Conv2d(1, 6, 5)` + relu | `32 - 5 + 1 = 28` | `[1, 6, 28, 28]` |
| S2 | `max_pool2d(2, 2)` | `28 / 2 = 14` | `[1, 6, 14, 14]` |
| C3 | `Conv2d(6, 16, 5)` + relu | `14 - 5 + 1 = 10` | `[1, 16, 10, 10]` |
| S4 | `max_pool2d(2, 2)` | `10 / 2 = 5` | `[1, 16, 5, 5]` |
| flatten | `torch.flatten(s4, 1)` | `16 × 5 × 5 = 400` | `[1, 400]` |
| F5 | `Linear(400, 120)` + relu | — | `[1, 120]` |
| F6 | `Linear(120, 84)` + relu | — | `[1, 84]` |
| 输出 | `Linear(84, 10)` | — | `[1, 10]` |

`fc1 = nn.Linear(16 * 5 * 5, 120)` 里的 `400`，正是表格里 flatten 那一行算出来的 `16×5×5`——**这个数字不是随手拍出来的，而是严格由"输入图像尺寸 32×32 → 两次卷积 → 两次池化"这条链路推导出来的**。如果换一个输入尺寸（比如 `28×28`，MNIST 的原始尺寸），这条链路上所有的中间尺寸都要重新推一遍，`fc1` 的输入维度也要跟着改，否则 `forward()` 跑到 `self.fc1(s4)` 这一步会直接报形状不匹配的错误。

**不确定手推对不对？可以直接跑代码验证**（打印每一步中间结果的 shape，比死记公式更保险）：

```python
x = torch.randn(1, 1, 32, 32)
x = F.relu(net.conv1(x)); print(x.shape)   # torch.Size([1, 6, 28, 28])
x = F.max_pool2d(x, 2);    print(x.shape)   # torch.Size([1, 6, 14, 14])
x = F.relu(net.conv2(x)); print(x.shape)   # torch.Size([1, 16, 10, 10])
x = F.max_pool2d(x, 2);    print(x.shape)   # torch.Size([1, 16, 5, 5])
x = torch.flatten(x, 1);   print(x.shape)   # torch.Size([1, 400])   <- 这就是 fc1 的输入维度
```

## 5. 网络的可学习参数：`nn.Parameter` 与 `net.parameters()`

```python
params = list(net.parameters())
print(len(params))          # 10
print(params[0].size())      # torch.Size([6, 1, 5, 5])   —— conv1.weight
```

`nn.Conv2d`、`nn.Linear` 这些层内部会自动创建 `weight`（和默认开启的 `bias`），类型是 `nn.Parameter`——**`nn.Parameter` 本质是 `torch.Tensor` 的一个子类，唯一的区别是它默认 `requires_grad=True`，并且被赋值给 `nn.Module` 的属性时会自动注册进该模块的参数列表**。呼应 [02_自动微分.md 第1.1节](./02_自动微分.md#1-预备知识常用-api-速查) 讲过的："标量、张量" 都是同一个 `torch.Tensor` 类的实例；这里同理，`nn.Parameter` 也不是什么特殊的新概念，只是 `Tensor` 加了"默认追踪梯度 + 自动注册"这两个便利。

`len(params) == 10` 是因为 `conv1`、`conv2`、`fc1`、`fc2`、`fc3` 一共 5 层，每层都有 `weight` 和 `bias` 两个参数张量，`5 × 2 = 10`。`net.parameters()` 会**递归遍历**整个网络（包括嵌套的子模块），把所有注册过的 `nn.Parameter` 按定义顺序收集起来返回——这也是为什么第8、9节 `loss.backward()` 之后，可以直接用一个 `for` 循环遍历 `net.parameters()` 去更新所有层的权重，不需要对每一层手写 `conv1.weight`、`conv1.bias`、`conv2.weight`……这样重复的代码。

## 6. 前向传播：为什么输入形状必须是 `[N, C, H, W]`

```python
input = torch.randn(1, 1, 32, 32)
out = net(input)
print(out)
# tensor([[ 0.0587,  0.0247, -0.0328, -0.1338, -0.0797, -0.0722,
#           0.0421,  0.1194,  0.0508, -0.0575]], grad_fn=<AddmmBackward0>)
```

`torch.nn` 里的层（`nn.Conv2d`、`nn.Linear`……）**只接受带 mini-batch 维度的输入**，四个维度依次是：

$$[\,N\ (\text{batch size}),\ C\ (\text{channel}),\ H\ (\text{height}),\ W\ (\text{width})\,]$$

哪怕只想输入"一张"图片，也必须补出这个 batch 维度（本例 `input.shape == [1, 1, 32, 32]`，第一个 `1` 就是 batch size，表示"这一批只有1张图"）。如果手头的数据只是单张 `[C, H, W]` 的形式，需要用 `input.unsqueeze(0)` 在最前面插一维，伪装成 batch size 为1的批次，再喂给网络——这是 `torch.nn` 的设计约定，为的是让同一套代码不用改就能同时处理单张图和一批图，训练时几乎总是成批喂数据以提升效率。

`out` 打印结果里的 `grad_fn=<AddmmBackward0>`，说明 `out` 不是叶子节点，而是由一连串矩阵运算（`Addmm` = 矩阵乘法+偏置加法，对应最后一层 `fc3` 的 `y = Wx + b`）产生的——这正是 [02_自动微分.md 第4节](./02_自动微分.md#4-计算图是怎么建立的grad_fn-链条) 讲的 `grad_fn` 链条，只不过这次的计算图比标量例子复杂得多、深得多（每一层卷积、每一次 relu、每一次全连接都会在图上多加几个节点）。

`out` 的 shape 是 `[1, 10]`，不是标量，所以如果想现在就试一下反向传播，必须按 [02_自动微分.md 第8.1节](./02_自动微分.md#81-非标量输出必须传-gradient-参数) 讲的方式，显式传入一个同形状的 `gradient`：

```python
net.zero_grad()                       # 先清空梯度（第8节详述）
out.backward(torch.randn(1, 10))      # out 非标量，必须传 gradient 参数
```

实际训练时几乎不会这样直接对网络输出反向传播——通常的做法是先用损失函数把 `out` 归约成一个标量 `loss`，再对 `loss` 调用 `backward()`，见下一节。

## 7. 损失函数：`nn.MSELoss` 与损失背后的计算图

**损失函数**接收一对 `(output, target)`，算出一个标量，衡量"网络的预测离真实答案有多远"。`torch.nn` 下有很多现成的损失函数，这里用最简单的均方误差 `nn.MSELoss`（Mean Squared Error）举例：

```python
output = net(input)
target = torch.randn(10)     # 假设的真实标签，实际场景中来自数据集
target = target.view(1, -1)   # 调整成和 output 一样的形状 [1, 10]
criterion = nn.MSELoss()

loss = criterion(output, target)
print(loss)
# tensor(1.3236, grad_fn=<MseLossBackward0>)
```

`nn.MSELoss()` 算的是 `output` 和 `target` 逐元素差值平方后的均值：

$$\text{loss} = \frac{1}{n}\sum_{i=1}^{n}(output_i - target_i)^2$$

这里 `n=10`（输出的10个分量），结果 `loss` 是形状 `torch.Size([])` 的**0维标量**——呼应 [02_自动微分.md 第1.1节](./02_自动微分.md#11-标量scalar与张量tensor的区别) 讲过的判断标准：`tensor(1.3236, ...)` 没有中括号，`.dim()==0`，正因为它是标量，才能像下一节那样直接 `loss.backward()`，不需要额外传 `gradient` 参数。

**顺着 `grad_fn` 往回看，整个网络此刻已经是一张完整的计算图**（对应 [02_自动微分.md 第4节](./02_自动微分.md#4-计算图是怎么建立的grad_fn-链条) 讲的链条，只是这次链条串起了卷积、池化、全连接、relu、MSE 一大串真实的网络层）：

```python
print(loss.grad_fn)                                    # MseLossBackward0
print(loss.grad_fn.next_functions[0][0])                 # AddmmBackward0     （fc3）
print(loss.grad_fn.next_functions[0][0].next_functions[0][0])  # AccumulateGrad / ReluBackward0（fc2 的 relu）
```

```
loss -> MseLossBackward0
     -> AddmmBackward0                （fc3：最后一层全连接）
     -> ReluBackward0                  （fc2 的 relu 激活）
     -> AddmmBackward0                （fc2）
     -> ReluBackward0                  （fc1 的 relu 激活）
     -> AddmmBackward0                （fc1）
     -> ViewBackward0                  （flatten）
     -> MaxPool2DWithIndicesBackward0（S4 池化）
     -> ReluBackward0                  （C3 的 relu）
     -> ConvolutionBackward0          （conv2）
     -> MaxPool2DWithIndicesBackward0（S2 池化）
     -> ReluBackward0                  （C1 的 relu）
     -> ConvolutionBackward0          （conv1）
     -> AccumulateGrad                 （叶子节点：conv1.weight / conv1.bias）
```

调用 `loss.backward()` 时，PyTorch 就是沿着这整条链，从 `loss` 一路反向走到最底部的 `conv1.weight`、`conv1.bias` 等所有叶子参数，逐层套用链式法则——原理和 [02_自动微分.md 第5.1节](./02_自动微分.md#51-补充例子三层链式法则-a--b--c--out-多个-retain_grad) 里三层链式法则的手工推导完全一样，只是这里的"层数"从3层变成了十几层，而且每一层不再是简单的 `+`、`*`，是卷积、池化这些更复杂的运算——**但反向传播的核心逻辑不变：每个节点只需要知道自己的局部导数，链式法则负责把它们串起来**。

## 8. 反向传播：`loss.backward()` 与 `net.zero_grad()`

```python
net.zero_grad()      # 清空所有参数的 .grad，等价于对每个参数调用 p.grad.zero_()
print('conv1.bias.grad before backward')
print(net.conv1.bias.grad)          # None（还没做过反向传播）

loss.backward()

print('conv1.bias.grad after backward')
print(net.conv1.bias.grad)
# tensor([ 0.0084, -0.0056, -0.0146, -0.0047,  0.0080,  0.0005])
```

**为什么反向传播之前一定要先 `zero_grad()`？** 这正是 [02_自动微分.md 第9节](./02_自动微分.md#9-梯度累积为什么每次都要-zero_grad) 讲过的：`.grad` 默认是**累加**，不是覆盖。如果不清零，下一次 `loss.backward()` 算出的新梯度会**叠加**在上一轮训练留下的旧梯度上，导致更新方向和幅度都不对——这在训练循环里是必须养成的习惯，本例里 `net.zero_grad()` 就是把这个操作一次性套用到网络的**所有**参数上，等价于对 `net.parameters()` 里每一个张量都调用一次 `.grad.zero_()`（或者第一次调用前 `.grad` 还是 `None`，`zero_grad()` 会正确处理这个初始状态）。

**`loss.backward()` 不需要传 `gradient` 参数**，因为 `loss` 本身已经是标量（第7节），对应 [02_自动微分.md 第3.1节](./02_自动微分.md#31-补充例子张量版的完整链路-x--y--z--out) 讲过的规则："标量的 `backward()` 等价于 `backward(torch.tensor(1.))`"。反向传播结束后，`net` 里**所有** `requires_grad=True` 的叶子参数（`conv1.weight`、`conv1.bias`、`conv2.weight`……)都会被填上各自的梯度，写入对应的 `.grad`。

## 9. 更新权重：手写 SGD 公式 vs `torch.optim`

有了梯度之后，最简单的参数更新规则是**随机梯度下降（Stochastic Gradient Descent, SGD）**：

$$\text{weight} \leftarrow \text{weight} - \text{learning\_rate} \times \text{weight.grad}$$

### 9.1 手写版本

```python
learning_rate = 0.01
for f in net.parameters():
    f.data.sub_(f.grad.data * learning_rate)
```

这里用 `f.data` 而不是直接对 `f` 做运算，原因呼应 [02_自动微分.md 第10节](./02_自动微分.md#10-阻止梯度追踪torchno_grad--detach--requires_grad_) 讲的"阻止梯度追踪"：**更新参数这个操作本身，不应该被计入计算图、也不应该产生新的梯度记录**——如果直接写 `f = f - learning_rate * f.grad`，这行代码自己也是一次张量运算，会被 autograd 记录下来，破坏了 `f` 作为叶子节点的身份，而且没有必要（更新权重是"事后处理数值"，不是模型前向计算的一部分）。`.data` 是访问同一块底层数据、但脱离 autograd 追踪的旧式写法；更推荐、更现代的写法是用 `torch.no_grad()` 包裹：

```python
learning_rate = 0.01
with torch.no_grad():
    for f in net.parameters():
        f -= learning_rate * f.grad
```

### 9.2 用 `torch.optim` 封装同样的逻辑

手写 SGD 只是最简单的一种规则；实际项目里几乎不会手写更新公式，而是用 `torch.optim` 提供的现成优化器（`SGD`、`Adam`、`RMSprop`……），把"用什么规则更新参数"这件事封装起来：

```python
import torch.optim as optim

optimizer = optim.SGD(net.parameters(), lr=0.01)

# 单次训练迭代的写法：
optimizer.zero_grad()           # 等价于第8节的 net.zero_grad()
output = net(input)
loss = criterion(output, target)
loss.backward()
optimizer.step()                 # 按 SGD 规则，用刚算出的梯度更新所有参数
```

`optimizer.zero_grad()` 和 `net.zero_grad()` 效果一致（因为创建 `optimizer` 时传入的就是 `net.parameters()`，两者操作的是同一组参数张量）；`optimizer.step()` 内部做的事，本质上就是 9.1 节里那个 `with torch.no_grad(): ...` 循环，只是把"学习率是多少"、"用 SGD 还是 Adam 的更新规则"这些细节都封装进了 `optimizer` 对象，换一种优化算法只需要换一行 `optim.XXX(...)`，不需要改训练循环的其余代码。

## 10. 串成完整的训练循环

把前面几节串起来，就是一个神经网络最基本的训练循环骨架（对应 [02_自动微分.md 第2.4节](./02_自动微分.md#24-图示正向传播与反向传播) 图示里"从输入到参数更新"的完整链路，这里补上了损失函数和网络定义的具体细节）：

```python
criterion = nn.MSELoss()
optimizer = optim.SGD(net.parameters(), lr=0.01)

for input, target in dataloader:      # 伪代码：实际数据从 DataLoader 里取
    optimizer.zero_grad()               # 第8节：清空上一轮遗留的梯度
    output = net(input)                  # 第6节：前向传播，顺带建好计算图
    loss = criterion(output, target)     # 第7节：算出标量 loss
    loss.backward()                      # 第8节：反向传播，算出所有参数的梯度
    optimizer.step()                     # 第9节：用梯度更新参数
```

五行代码，各自对应一个不可省略的步骤：**不清零就会梯度累积、不前向就没有计算图、不算 loss 就没有反向传播的起点、不反向传播就没有梯度、不 `step()` 参数就永远不会更新**——训练一个神经网络，本质上就是把这五步在数据上反复循环执行。

## 11. API 规范速查：`nn.Conv2d`、`nn.Linear`、`F` 中用到的函数

前面几节用到的每一个 API，这里单独整理成速查表——**签名、每个参数的含义与默认值、输入/输出形状、内部权重形状**，方便不用翻前面的段落就能直接查。

### 11.1 `nn.Conv2d`：二维卷积层

```python
nn.Conv2d(in_channels, out_channels, kernel_size, stride=1, padding=0,
          dilation=1, groups=1, bias=True, padding_mode='zeros')
```

| 参数 | 含义 | 默认值 | 本文示例取值 |
|---|---|---|---|
| `in_channels` | 输入的通道数（比如灰度图是1，RGB图是3） | 必填 | `conv1`: `1`；`conv2`: `6`（等于上一层的输出通道数） |
| `out_channels` | 输出的通道数，即这一层用多少个不同的卷积核 | 必填 | `conv1`: `6`；`conv2`: `16` |
| `kernel_size` | 卷积核尺寸，整数（正方形）或 `(kH, kW)` 元组 | 必填 | `5`（等价于 `(5, 5)`） |
| `stride` | 卷积核每次滑动的步长 | `1` | 未传，用默认值 `1` |
| `padding` | 输入四周补零的圈数 | `0` | 未传，用默认值 `0` |
| `dilation` | 卷积核内部元素之间的间隔（空洞卷积用） | `1` | 未传，用默认值 `1` |
| `groups` | 分组卷积的组数，`1` 表示普通卷积（不分组） | `1` | 未传，用默认值 `1` |
| `bias` | 是否带偏置项 | `True` | 未传，用默认值 `True` |
| `padding_mode` | 补零的方式（`'zeros'`/`'reflect'`/`'replicate'`/`'circular'`） | `'zeros'` | 未传，用默认值 |

- **输入 shape**：`[N, in_channels, H_in, W_in]`（第6节讲过的 mini-batch 约定）。
- **输出 shape**：`[N, out_channels, H_out, W_out]`，`H_out`/`W_out` 按第4.2节的公式计算：$\text{out}=\lfloor(\text{in}+2\text{padding}-\text{kernel\_size})/\text{stride}\rfloor+1$。
- **内部可学习参数**（对应第5节 `net.parameters()` 里能取到的张量）：
  - `weight`：shape 为 `[out_channels, in_channels/groups, kH, kW]`，比如 `conv1.weight.shape == [6, 1, 5, 5]`（第5节 `params[0].size()` 打印的正是这个）。
  - `bias`：shape 为 `[out_channels]`，比如 `conv1.bias.shape == [6]`。

```python
conv1 = nn.Conv2d(1, 6, 5)
print(conv1.weight.shape)   # torch.Size([6, 1, 5, 5])
print(conv1.bias.shape)      # torch.Size([6])

x = torch.randn(1, 1, 32, 32)
y = conv1(x)
print(y.shape)                # torch.Size([1, 6, 28, 28])   —— 32-5+1=28
```

### 11.2 `nn.Linear`：全连接层（仿射变换 `y = xW^T + b`）

```python
nn.Linear(in_features, out_features, bias=True)
```

| 参数 | 含义 | 默认值 | 本文示例取值 |
|---|---|---|---|
| `in_features` | 输入向量的维度 | 必填 | `fc1`: `400`（=`16*5*5`，第4节推导）；`fc2`: `120`；`fc3`: `84` |
| `out_features` | 输出向量的维度 | 必填 | `fc1`: `120`；`fc2`: `84`；`fc3`: `10` |
| `bias` | 是否带偏置项 | `True` | 未传，用默认值 `True` |

- **输入 shape**：`[*, in_features]`——`*` 表示可以有任意多个"前置维度"（最常见的就是 batch 维 `[N, in_features]`），`Linear` 只关心最后一维必须等于 `in_features`。
- **输出 shape**：`[*, out_features]`，前置维度不变，只有最后一维从 `in_features` 变成 `out_features`。
- **内部可学习参数**：
  - `weight`：shape 为 `[out_features, in_features]`（注意顺序是"输出在前、输入在后"，因为内部实际计算是 `x @ weight.T + bias`），比如 `fc1.weight.shape == [120, 400]`。
  - `bias`：shape 为 `[out_features]`，比如 `fc1.bias.shape == [120]`。

```python
fc1 = nn.Linear(400, 120)
print(fc1.weight.shape)   # torch.Size([120, 400])
print(fc1.bias.shape)      # torch.Size([120])

x = torch.randn(1, 400)
y = fc1(x)
print(y.shape)               # torch.Size([1, 120])
```

### 11.3 `torch.nn.functional` 中用到的函数

| API | 签名 | 关键参数 | 作用 | 输出 shape |
|---|---|---|---|---|
| `F.relu` | `F.relu(input, inplace=False)` | `inplace`：是否原地修改 `input`（省内存，但会破坏原张量，调试时不建议开） | 逐元素计算 $\max(0, x)$，小于0的置为0，大于0的原样保留 | 与 `input` 完全相同 |
| `F.max_pool2d` | `F.max_pool2d(input, kernel_size, stride=None, padding=0, dilation=1, ceil_mode=False, return_indices=False)` | `kernel_size`：池化窗口大小，整数或元组，正方形窗口可只传一个整数（第2.1节讲过）；`stride`：默认等于 `kernel_size`（即不重叠地滑动）；`padding`：窗口外补的负无穷/边界值圈数 | 在每个窗口内取最大值，实现下采样 | `[N, C, H_out, W_out]`，公式同卷积（`kernel_size` 当作卷积核代入第4.2节公式） |
| `torch.flatten`（不在 `F` 里，但常和上面两个一起用于展平） | `torch.flatten(input, start_dim=0, end_dim=-1)` | `start_dim`：从第几维开始展平（本文档统一传 `1`，跳过第0维的 batch）；`end_dim`：展平到第几维为止，默认到最后一维 | 把 `[start_dim, end_dim]` 范围内的维度压成一维 | 例如 `[N, C, H, W]` 传 `start_dim=1` 后变成 `[N, C*H*W]` |

```python
x = torch.tensor([-2.0, -0.5, 0.0, 3.0])
print(F.relu(x))                # tensor([0., 0., 0., 3.])

x = torch.randn(1, 6, 28, 28)
y = F.max_pool2d(x, 2)            # 等价于 F.max_pool2d(x, kernel_size=2)，stride 默认等于 kernel_size=2
print(y.shape)                     # torch.Size([1, 6, 14, 14])

x = torch.randn(1, 16, 5, 5)
y = torch.flatten(x, 1)
print(y.shape)                     # torch.Size([1, 400])
```

| API | 签名 | 关键参数 |
|---|---|---|
| `nn.MSELoss` | `nn.MSELoss(reduction='mean')` | `reduction`：`'mean'`（默认，取平均）/`'sum'`（求和）/`'none'`（不归约，逐元素返回） |
| `optim.SGD` | `optim.SGD(params, lr, momentum=0, weight_decay=0)` | `params`：要优化的参数，通常传 `net.parameters()`；`lr`：学习率，必填；`momentum`：动量系数，默认不启用 |

## 12. 本文档之外：训练真实网络还会用到的几类 API

前面11节覆盖了 LeNet-5 这个例子本身用到的所有 API，但真实项目里训练一个网络，还会立刻撞到几类这里完全没提过的调用——提前列出来，免得下一步学习时觉得"怎么冒出来这么多没见过的东西"。

### 12.1 训练/推理模式切换：`net.train()` / `net.eval()`

```python
net.train()   # 切换到"训练模式"（默认就是这个状态）
net.eval()     # 切换到"推理/评估模式"
```

LeNet 这个例子里没有用到 `Dropout`、`BatchNorm` 这类**训练和推理时行为不一样**的层，所以到目前为止不调用 `train()`/`eval()` 也不会有问题。但只要网络里出现了这两种层（后面章节几乎必然会遇到），忘记切换会导致：

- **`Dropout`**：训练时随机丢弃一部分神经元（防止过拟合），推理时必须**关闭丢弃、用全部神经元**——不调用 `net.eval()` 的话，推理结果每次都会不一样，而且比训练时表现更差。
- **`BatchNorm`**：训练时用**当前这批数据**的均值/方差做归一化，推理时必须用**训练过程中累积下来**的全局均值/方差——不切换模式，单张图片推理时会因为"batch 只有1个样本"算不出有意义的方差而报错或者结果异常。

`net.train()`/`net.eval()` 只是**修改一个内部标志位**，本身不涉及梯度、不涉及计算图，随时可以切换，习惯上是"训练循环开始前调用一次 `train()`，验证/推理前调用一次 `eval()`"。

### 12.2 GPU 相关：`.to(device)`

```python
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")   # 有 GPU 就用 GPU，没有就退回 CPU
net = net.to(device)          # 把网络的所有参数搬到 device 上
input = input.to(device)       # 把输入数据也搬到同一个 device 上
```

**关键约束：参与同一次运算的所有张量，必须在同一个 device 上**（要么全在 CPU，要么全在同一块 GPU），否则会报 `Expected all tensors to be on the same device` 这类错误。`net.to(device)`、`tensor.to(device)` 做的事情是把底层数据搬到对应的硬件上，之后 `net(input)` 才能利用 GPU 加速——本文档所有例子都省略了这一步（默认在 CPU 上跑，方便新手直接复制运行），实际训练稍大的网络时，这是标配的第一步。

### 12.3 模型保存与加载：`torch.save` / `torch.load`

训练完的网络参数需要能存下来、之后能加载回来复用，不然每次都要重新训练：

```python
torch.save(net.state_dict(), 'model_weights.pth')   # 只保存参数（推荐做法）

net2 = Net()                                              # 必须先有一个同结构的网络实例
net2.load_state_dict(torch.load('model_weights.pth'))     # 把保存的参数加载进去
net2.eval()                                                 # 加载完通常紧接着切到推理模式（第12.1节）
```

`net.state_dict()` 返回一个**有序字典**，key 是参数名（比如 `'conv1.weight'`、`'fc1.bias'`），value 是对应的张量——这正是第5节 `net.parameters()` 那些参数的"带名字"版本。保存/加载 `state_dict` 是官方推荐的方式（只存数值，体积小、跨版本兼容性好），而不是直接 `torch.save(net, ...)` 整个模型对象（那种方式会把类定义也序列化进去，换个 Python/PyTorch 版本容易加载失败）。

### 12.4 形状变换：`view` / `reshape` / `unsqueeze` / `squeeze`，与 `flatten` 对照

第2.1节和第6节各用了一次 `.view()`、`.unsqueeze()`，但没有集中说明——这几个都是"改变张量形状、不改变里面的数值"的操作，放在一起对比：

| API | 作用 | 示例 |
|---|---|---|
| `x.view(*shape)` | 按新形状重新解释底层数据，**要求原张量在内存里是连续的**（`.is_contiguous()` 为 `True`），否则报错 | `x.view(-1, 400)` |
| `x.reshape(*shape)` | 效果和 `view` 一样，但如果原张量不连续，会自动**先拷贝一份**再改形状，不会报错 | `x.reshape(-1, 400)` |
| `torch.flatten(x, start_dim)` | 把指定范围的维度压成一维，语义比 `view`/`reshape` 更聚焦（专门用来"展平"），第11.3节已介绍 | `torch.flatten(x, 1)` |
| `x.unsqueeze(dim)` | 在第 `dim` 个位置**插入一个大小为1的新维度** | `x.unsqueeze(0)`：`[C,H,W]` → `[1,C,H,W]`（第6节"补出 batch 维"用的就是它） |
| `x.squeeze(dim)` | 把第 `dim` 个维度**删掉**（前提是这一维大小恰好是1）；不传 `dim` 则删掉所有大小为1的维度 | `x.squeeze(0)`：`[1,C,H,W]` → `[C,H,W]` |

**该用哪个？** 新手不确定原张量是否连续时，优先用 `reshape`（更不容易报错）；明确知道是"展平成二维"这种场景，`flatten` 语义最清楚；需要"凭空插入/删除一个大小为1的维度"（最典型就是 batch 维），用 `unsqueeze`/`squeeze`，不要用 `view`/`reshape` 硬算，容易算错剩下的数字。

### 12.5 一个容易被忽略的坑：`nn.MSELoss` 其实不适合这个10分类任务

第7节用 `nn.MSELoss` 只是为了**照抄官方教程、演示"损失函数怎么用"这个流程**，但如果认真做"识别0~9手写数字"这个分类任务，更合适的损失函数是 `nn.CrossEntropyLoss`：

```python
criterion = nn.CrossEntropyLoss()

output = net(input)              # shape [N, 10]，10个类别的原始分数（logits），不需要提前做 softmax
target = torch.tensor([3])        # 注意：这里是类别的整数下标（0~9），不是第7节那种和 output 同形状的浮点向量！
loss = criterion(output, target)
```

`MSELoss` 衡量的是"两个数值向量差多远"，适合**回归**任务（预测一个连续数值）；`CrossEntropyLoss` 衡量的是"预测的概率分布和真实类别差多远"，适合**分类**任务（预测"是哪一类"）——LeNet 输出的10个分数本质上是"10个类别各自的可能性"，属于分类问题，训练效果上 `CrossEntropyLoss` 通常明显优于 `MSELoss`。官方教程这里用 `MSELoss` 纯粹是因为它是本系列教程里第一次出现损失函数，选一个最简单、最容易讲清楚公式的；等到专门讲图像分类训练的章节，会换成 `CrossEntropyLoss`。

### 12.6 训练循环里的 `dataloader` 是什么：留到下一章

第10节训练循环里写的 `for input, target in dataloader:` 只是**伪代码**，`dataloader` 具体是什么、数据从哪来、`torch.utils.data.Dataset` / `DataLoader` 怎么配合使用，本文档没有展开——这部分内容留到下一章专门讲数据加载和完整训练流程时再详细说明，这里先知道"训练循环需要一个能一批批吐出 `(input, target)` 的东西"就够了。

### 12.7 张量的维度数没有上限，但 `Conv1d/2d/3d` 只到3维——这是运算逻辑的限制，不是张量本身的限制

**这一点对初学者极其重要，也是最容易搞混的一点：`nn.Conv2d` 名字里的"2"，指的是"卷积核在几个方向上滑动"，不是"这个张量总共有几维"。** 两个"维度"是完全不同的概念，混在一起想就会误以为"PyTorch 的张量最多只能有3维"。

**张量本身能创建任意多维，和 `Conv2d` 无关：**

```python
import torch
import torch.nn as nn

# 直接创建一个10维张量，10个数字 = 10个维度，没有任何报错
w = torch.randn(2, 3, 2, 2, 3, 2, 2, 3, 2, 2)
print(w.dim())     # 10
print(w.shape)      # torch.Size([2, 3, 2, 2, 3, 2, 2, 3, 2, 2])
```

PyTorch 内部对张量维度数的硬性上限远高于10（几十维这个量级），日常写代码根本碰不到这个上限——**能不能创建，纯粹取决于内存装不装得下，不取决于"维度数"这个数字本身**。

**只要包一层 `nn.Parameter`，10维张量一样能当"可学习权重"用**（呼应第5节 `nn.Parameter` 的机制，和维度数无关）：

```python
class MyModule(nn.Module):
    def __init__(self):
        super().__init__()
        self.weight = nn.Parameter(torch.randn(2, 3, 2, 2, 3, 2, 2, 3, 2, 2))   # 10维权重，一样能被 net.parameters() 找到、一样能求梯度

    def forward(self, x):
        ...   # 具体怎么用这个10维权重做运算，需要自己定义
```

**真正的限制在于：`Conv2d` 不只是"一个张量"，而是"一个张量 + 一整套配套的卷积运算规则"。** PyTorch 提供了 `Conv1d`（1个方向滑动，用于序列）、`Conv2d`（2个方向滑动，用于图像）、`Conv3d`（3个方向滑动，用于体数据/视频）这三种**现成封装好"怎么滑动、怎么乘加"运算逻辑**的层（第12.2节表格对照过 shape），但**没有 `Conv10d` 这种东西**——不是张量创建不出10维，而是没有人在框架层面定义"卷积核该怎么在10个方向上滑动"这套运算规则。如果非要用10维权重做类似卷积的运算，得自己用 `torch.einsum`/`torch.tensordot` 手写"哪些维度相乘、哪些维度求和"的规则，PyTorch 不会替你决定这套规则该怎么设计。

**一句话记住这个区别：`torch.randn(...)` 想传几个数字就传几个数字，创建张量维度数几乎没有实际限制；`nn.ConvXd`、`nn.Linear` 这些"层"，维度数受限于"这个运算规则设计到了几维"，是 API 设计的边界，不是张量本身的边界。**

## 13. 要点小结

- **`nn`（层，有状态）vs `nn.functional`（函数，无状态）**：有可学习参数的操作用 `nn.` 类在 `__init__` 里创建，没有参数的纯变换用 `F.` 函数在 `forward()` 里直接调。
- **"创建网络"就是实例化一次 `Net()`，"使用网络"就是调用 `net(input)`**：第3节给了一个从 `pip install torch` 到打印输出的完整最小示例，卡住时回去对照那四步（创建网络 → 造输入 → 使用网络 → 看输出）。
- **自定义网络必须继承 `nn.Module`，`__init__` 里先调 `super().__init__()`**：这一步让后续 `self.xxx = nn.Conv2d(...)` 这类赋值能被自动注册进模块的参数簿记，进而被 `net.parameters()` 找到。
- **只需要写 `forward()`，`backward()` 由 autograd 自动完成**：`forward()` 里的每一步都是普通张量运算，执行时同步建立计算图，原理和 [02_自动微分.md](./02_自动微分.md) 完全一样，只是这次的图更深、更复杂。
- **输入必须带 mini-batch 维度 `[N, C, H, W]`**，单张图片要用 `unsqueeze(0)` 补出这一维。
- **卷积/池化会改变空间尺寸，全连接层的输入维度要手工推算**（第4节公式 + 逐层验算表格，也可以直接打印中间 shape 验证），这是最容易踩坑、报形状不匹配错误的地方。
- **`net.zero_grad()` / `optimizer.zero_grad()` 是每次反向传播前的必要步骤**，原因见 [02_自动微分.md 第9节](./02_自动微分.md#9-梯度累积为什么每次都要-zero_grad)：梯度默认累加，不清零就会越滚越大、方向出错。
- **更新参数要在 `torch.no_grad()`（或旧式 `.data`）下进行**，避免"更新权重"这个动作本身被计入计算图，呼应 [02_自动微分.md 第10节](./02_自动微分.md#10-阻止梯度追踪torchno_grad--detach--requires_grad_)。
- **`torch.optim` 把"更新规则"封装成了可替换的组件**：训练循环的结构（`zero_grad → forward → loss → backward → step`）不变，换优化算法只需要换 `optimizer` 的构造方式。
- **忘了某个 API 的参数/形状怎么办**：查第11节的速查表——`nn.Conv2d`、`nn.Linear` 的参数含义与权重形状，`F.relu`、`F.max_pool2d`、`torch.flatten` 的签名与输入输出形状都整理在那里，不用翻代码或查官方文档。
- **这份文档不等于"神经网络需要的全部 API"**：`train()`/`eval()` 模式切换、`.to(device)`、模型保存加载、`CrossEntropyLoss` 这些第12节列的内容，训练真实网络时几乎都会用到，只是 LeNet 这个最小例子暂时用不上——不需要现在就全部记住，用到时回第12节查，或者像上一轮聊到的那样直接在 IDEA 里用 `Ctrl+P`/`Ctrl+Q` 现查签名和文档。
- **张量维度数 ≠ `ConvXd` 里的数字**：`torch.randn(...)` 想创建几维张量都行（第12.7节），`Conv1d/2d/3d` 只到3维是因为 PyTorch 只封装了这三种"卷积核怎么滑动"的运算规则，不是张量本身有维度上限——别把"运算逻辑的边界"和"数据结构的边界"搞混。

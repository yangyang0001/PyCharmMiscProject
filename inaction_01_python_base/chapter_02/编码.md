# ASCII、Unicode、UTF-8 到底是什么关系

## 一句话理解

- **ASCII**：一张很小的"字符对照表"，只收录了英文字母、数字、标点，一共 128 个字符。
- **Unicode**：一张超级大的"字符对照表"，把世界上几乎所有文字（中文、日文、emoji……）都编了号，目前有 15 万+ 个字符。
- **UTF-8**：把 Unicode 的号码翻译成计算机里实际存储的**字节**的一种"翻译方法"（编码方式）。

三者的关系可以理解成：

```
ASCII  ⊂  Unicode  ——(用 UTF-8 这种规则存成字节)——>  硬盘/网络里的 01 数据
```

Unicode 里前 128 个字符，编号和 ASCII 完全一样，所以 **ASCII 是 Unicode 的一个子集**。

## 为什么需要这三样东西

### 1. ASCII：够用，但太小气

计算机最早是美国人发明的，一个字节（8 位）能表示 0~255，256 种可能。英文字母 + 数字 + 常用符号凑一凑，用 128 个就够了（0~127），这就是 ASCII。

比如：
- 大写字母 `A` 对应数字 `65`
- 数字字符 `'0'` 对应数字 `48`

问题：**中文有几万个字**，128 个编号根本不够用。

### 2. Unicode：给全世界文字发"身份证号"

Unicode 的目标很单纯：**给每一个字符分配一个唯一的编号**（叫"码点"，code point），不管是英文、中文、日文还是 emoji。

比如：
- `A` 的 Unicode 编号是 `U+0041`（十进制 65，跟 ASCII 一样）
- `中` 的 Unicode 编号是 `U+4E2D`（十进制 20013）
- `😀` 的 Unicode 编号是 `U+1F600`

**注意**：Unicode 只规定"编号是多少"，**不规定这个编号在硬盘里怎么存**。这就是 UTF-8 要解决的问题。

### 3. UTF-8：把编号翻译成字节的规则

同一个 Unicode 编号，可以有不同的存储方式（UTF-8、UTF-16、UTF-32……），UTF-8 是目前网络和大多数系统的默认选择，因为它有两个优点：

- **兼容 ASCII**：编号 0~127 的字符，UTF-8 用 1 个字节存，内容和 ASCII 一模一样，老系统也能读懂。
- **变长省空间**：常用的英文字符只占 1 字节；中文这类字符通常占 3 字节；不常用的生僻字/emoji 可能占 4 字节。不会像 UTF-32 那样，不管什么字符都固定用 4 字节，浪费空间。

大致规则：

| 字符范围（Unicode 编号） | UTF-8 占用字节数 | 举例 |
|---|---|---|
| U+0000 ~ U+007F | 1 字节 | `A`、`0`、`!` |
| U+0080 ~ U+07FF | 2 字节 | 部分欧洲语言字符 |
| U+0800 ~ U+FFFF | 3 字节 | `中`、`文` |
| U+10000 ~ U+10FFFF | 4 字节 | 😀 等表情符号 |

## 一个类比

- **Unicode** 就像每个人的"身份证号码"——全球唯一，但号码本身不能直接印在纸上传输。
- **UTF-8** 就像把身份证号码"打包成快递包裹"的规则——规定了包裹用几个格子装、怎么拆开还原。
- **ASCII** 就像是"最早的一批身份证号"，恰好和 Unicode 前 128 个号码长得一样。

## Python 里怎么转换

Python 3 里的 `str` 字符串在内存中就是按 Unicode 字符处理的，转换主要靠两个函数：

```python
# 字符 -> Unicode 编号（十进制）
ord('A')        # 65
ord('中')       # 20013

# Unicode 编号 -> 字符
chr(65)          # 'A'
chr(20013)        # '中'

# 字符串 -> 字节（按 UTF-8 编码）
'中文'.encode('utf-8')   # b'\xe4\xb8\xad\xe6\x96\x87'  一个中文字占 3 字节

# 字节 -> 字符串（按 UTF-8 解码）
b'\xe4\xb8\xad\xe6\x96\x87'.decode('utf-8')  # '中文'
```

记住这个对应关系：

```
字符  --ord()-->  Unicode 编号  --encode('utf-8')-->  字节
字节  --decode('utf-8')-->  Unicode 编号  --chr()-->  字符
```

## encode 与 decode：一句话记住

- **encode**：文字 → 字节，要把字符串**发出去/存起来**时用（发网络、写二进制文件、算哈希）
- **decode**：字节 → 文字，把收到的字节**还原成能读的文字**时用（收网络数据、读二进制文件）

```python
'你好'.encode('utf-8')                        # str -> bytes
b'\xe4\xbd\xa0\xe5\xa5\xbd'.decode('utf-8')     # bytes -> str
```

日常用 `open(..., 'r')` 读写文本文件时，Python 已经自动帮你 encode/decode 了，不用手动调；只有直接接触"字节"的场景（网络通信、二进制文件、`hashlib` 算哈希）才需要自己调用。

## encode 能选哪些编码

Python 标准库自带 **100 多种编码**（`encode('编码名')` 里都能填），常用的按类别列一下：

| 类别 | 编码名 | 说明 |
|---|---|---|
| Unicode 系列 | `utf-8` | 首选，兼容 ASCII，变长省空间 |
| Unicode 系列 | `utf-16` / `utf-32` | 定长/半定长，Windows 部分场景会用到 |
| 中文 | `gbk` / `gb2312` / `gb18030` | 老的中文 Windows 系统、遗留项目 |
| 中文（港台） | `big5` | 繁体中文，港台老系统 |
| 日文 | `shift_jis` / `euc_jp` | 日文老系统常见编码 |
| 韩文 | `euc_kr` | 韩文老系统常见编码 |
| 西欧 | `latin-1`（`iso-8859-1`） | 0~255 都能编码，不会报错 |
| 英文 | `ascii` | 只支持英文数字符号，超出范围直接报错 |

查看完整列表：

```python
import encodings, pkgutil
[m.name for m in pkgutil.iter_modules(encodings.__path__)]
```

## 常见踩坑

- 打开文件/读网络数据报 `UnicodeDecodeError`，通常是**编码方式和存储时不一致**，比如文件是 GBK 存的，你却用 UTF-8 去 `decode`。
- `encode` 是"字符串变字节"（写文件、发网络请求前做），`decode` 是"字节变字符串"（读文件、收网络数据后做）——方向不要记反。
- 现在写代码，**没有特殊理由就统一用 UTF-8**，能少踩很多坑。

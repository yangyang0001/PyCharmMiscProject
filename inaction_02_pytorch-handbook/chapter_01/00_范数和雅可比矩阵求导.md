# 范数（Norm）

## 一句话定义

**范数**是衡量向量"大小/长度"的一种标准化方法。给定一个向量，范数把它映射成一个**非负实数**，这个数表示这个向量有多"大"。

数学记号：$\|x\|$，读作 "x 的范数"。

## 严格数学定义

设 $V$ 是一个向量空间（比如 $\mathbb{R}^n$）。**范数**是一个函数：

$$
\|\cdot\| : V \rightarrow \mathbb{R}_{\geq 0}
$$

即：把向量空间 $V$ 中的任意一个向量 $x$，映射到一个**非负实数** $\|x\|$，并且这个函数必须同时满足下面三条公理（缺一不可，否则不能叫"范数"）。

## 范数必须满足的三条性质

不是随便一个能算出数字的公式都能叫"范数"，必须同时满足：

1. **非负性**：$\|x\| \geq 0$，且 $\|x\| = 0 \iff x = 0$（只有零向量的范数才是0）
2. **齐次性（数乘）**：$\|\alpha x\| = |\alpha| \cdot \|x\|$（向量放大 α 倍，范数也放大 |α| 倍）
3. **三角不等式**：$\|x + y\| \leq \|x\| + \|y\|$（两边之和大于等于第三边，几何直觉）

## 常见的范数类型（Lp 范数家族）

对向量 $x = (x_1, x_2, \dots, x_n)$，**Lp 范数**定义为：

$$
\|x\|_p = \left( \sum_{i=1}^{n} |x_i|^p \right)^{1/p}
$$

### L1 范数（p=1）—— 曼哈顿范数

$$
\|x\|_1 = \sum_i |x_i|
$$

几何意义：像城市街区里从A点走到B点，只能沿着横平竖直的街道走，不能走对角线。

```python
import torch
x = torch.tensor([3.0, -4.0])
x.norm(p=1)   # |3| + |-4| = 7
```

### L2 范数（p=2）—— 欧几里得范数（默认）

$$
\|x\|_2 = \sqrt{\sum_i x_i^2}
$$

几何意义：两点间的直线距离（勾股定理）。这是**最常用**的范数，PyTorch 的 `.norm()` 默认就是它。

```python
x = torch.tensor([3.0, 4.0])
x.norm()        # 默认 p=2: sqrt(3^2+4^2) = sqrt(25) = 5
x.norm(p=2)     # 等价写法
```

### L∞ 范数（无穷范数）—— 取最大绝对值

$$
\|x\|_\infty = \max_i |x_i|
$$

```python
x = torch.tensor([3.0, -4.0, 1.0])
x.norm(p=float('inf'))   # max(|3|, |-4|, |1|) = 4
```

## 为什么深度学习里经常用到范数

| 用途 | 说明 |
|---|---|
| 衡量向量/梯度的大小 | 比如判断梯度是否爆炸（gradient explosion），常看梯度的 L2 范数 |
| 梯度裁剪（gradient clipping） | `torch.nn.utils.clip_grad_norm_()` 就是把梯度的范数限制在某个阈值以内 |
| 正则化（regularization） | L1 正则（产生稀疏解）、L2 正则（权重衰减 weight decay）本质就是在 loss 里加上权重的范数作为惩罚项 |
| 归一化（normalize） | 把向量除以自己的范数，得到长度为1的"单位向量"，只保留方向信息 |
| 衡量误差 | 比如两个向量的距离 $\|a - b\|_2$，常用来衡量预测值和真实值的差距 |

## norm() 和标准差（std）的区别

容易混淆的两个概念：

$$
\|x\|_2 = \sqrt{\sum_i x_i^2} \qquad \text{（不减均值，衡量离原点的距离）}
$$

$$
\text{std} = \sqrt{\frac{1}{n}\sum_i (x_i - \bar{x})^2} \qquad \text{（先减均值，衡量数据的离散程度）}
$$

给向量整体加一个常数（平移），`norm()` 的结果会剧烈变化，但 `std()` 不变——因为 norm 关心"离原点多远"，std 关心"数据彼此之间波动多大"。

## 矩阵也有范数

范数不仅适用于向量，也适用于矩阵，比如 Frobenius 范数（矩阵版的 L2 范数，把矩阵展平成向量再算）：

```python
A = torch.tensor([[1.0, 2.0], [3.0, 4.0]])
A.norm()   # 默认按 Frobenius 范数: sqrt(1^2+2^2+3^2+4^2) = sqrt(30)
```

## Vector-Jacobian Product（雅可比矩阵求导）

`torch.autograd` 本质上就是用来计算 **vector-Jacobian product（VJP）** 的工具。

### 为什么不直接算雅可比矩阵

对一个向量函数 $\vec{y} = f(\vec{x})$（$\vec{x} \in \mathbb{R}^n$，$\vec{y} \in \mathbb{R}^m$），完整的雅可比矩阵是一个 $m \times n$ 的矩阵：

$$
J=\begin{pmatrix}
\dfrac{\partial y_1}{\partial x_1} & \cdots & \dfrac{\partial y_1}{\partial x_n} \\
\vdots & \ddots & \vdots \\
\dfrac{\partial y_m}{\partial x_1} & \cdots & \dfrac{\partial y_m}{\partial x_n}
\end{pmatrix}
$$

深度学习中 $n, m$ 动辄百万级，把整个 $J$ 显式算出来存下来并不现实。但我们几乎从不需要完整的 $J$——真正需要的是：**给定某个标量 $l$ 关于 $\vec{y}$ 的梯度 $v = \dfrac{\partial l}{\partial \vec{y}}$，求 $l$ 关于 $\vec{x}$ 的梯度**。根据链式法则：

$$
\frac{\partial l}{\partial \vec{x}} = J^T \cdot v
$$

这就是 **vector-Jacobian product**：不需要显式构造 $J$，只需要计算 $J^T v$ 这一个乘积（autograd 内部通过反向传播高效完成）。这种特性使得把外部梯度传回一个输出为非标量的模型变得非常方便。

### 代码示例

```python
import torch

x = torch.randn(3, requires_grad=True)

y = x * 2
while y.data.norm() < 1000:
    y = y * 2

print(y)
# tensor([ 293.4463,   50.6356, 1031.2501], grad_fn=<MulBackward0>)
```

这里 `y` 不再是标量，`torch.autograd` 无法（也不必）直接算出完整的雅可比矩阵。但如果只想要 vector-Jacobian product，只需把向量 $v$ 作为参数传给 `backward`：

```python
gradients = torch.tensor([0.1, 1.0, 0.0001], dtype=torch.float)
y.backward(gradients)

print(x.grad)
# tensor([5.1200e+01, 5.1200e+02, 5.1200e-02])
```

### 结果是怎么来的

`y = x * 2^k`（$k$ 是循环放大的次数），所以雅可比矩阵是对角阵 $J = 2^k I$（每个 $y_i$ 只依赖对应的 $x_i$）。由 $\dfrac{\partial l}{\partial \vec{x}} = J^T v = 2^k \cdot v$，从结果反推：

$$
[51.2,\ 512,\ 0.0512] = 512 \times [0.1,\ 1.0,\ 0.0001]
$$

即这里 $2^k = 512 = 2^9$。

`y.backward(gradients)` 相当于告诉 autograd："假设有一个标量 $l$，它对 $y$ 的梯度恰好是 `gradients`"，autograd 沿计算图反向传播，算出这个假想的 $l$ 对 $x$ 的梯度——而不需要 $y$ 本身是标量。

### v 的完整推导：v 就是 ∂out/∂y

前面直接给出了 $\dfrac{\partial l}{\partial x}=J^Tv$，这里把 $v$ 到底是什么、从哪来，从头推一遍。

**真实设定**：`y` 从来不是计算图的终点，它后面几乎总还接着别的运算，最终汇聚成一个**标量** `out`（loss）：

$$
x \in \mathbb{R}^n \xrightarrow{\ f\ } y \in \mathbb{R}^m \xrightarrow{\ g\ } \text{out} \in \mathbb{R}
$$

即 $\text{out} = g(y) = g(f(x))$，我们要求的是 $\dfrac{\partial\,\text{out}}{\partial x}$。

**第一步——多元链式法则（推导的根，没有黑箱）**：$x_i$ 通过 $m$ 条路径（经过 $y_1,\dots,y_m$）影响 `out`，把每条路径的贡献加起来：

$$
\frac{\partial\,\text{out}}{\partial x_i} = \sum_{j=1}^m \frac{\partial\,\text{out}}{\partial y_j}\cdot\frac{\partial y_j}{\partial x_i}, \qquad i=1,\dots,n
$$

**第二步——改写成矩阵形式**：定义雅可比矩阵 $J\in\mathbb{R}^{m\times n}$（$J_{ji}=\partial y_j/\partial x_i$），再定义

$$
v_j := \frac{\partial\,\text{out}}{\partial y_j} \qquad \Longleftarrow \textbf{这就是 v 的定义：out 对 y 的梯度，不是 y 的数值}
$$

于是求和式变成矩阵乘法：

$$
\frac{\partial\,\text{out}}{\partial x_i} = \sum_j v_j J_{ji} = (J^T v)_i \quad\Longrightarrow\quad \boxed{\dfrac{\partial\,\text{out}}{\partial x} = J^T v}
$$

**第三步——`gradients` 参数就是在声明这个假设的 out**：不需要代码里真的写出 `out = ...`，调用 `y.backward(gradients)` 本身就等价于"假设存在一个标量 $\text{out}:=\text{gradients}^T y=\sum_j v_j y_j$"，验证一下：

$$
\frac{\partial\,\text{out}}{\partial y_j}=\frac{\partial}{\partial y_j}\Big(\sum_k v_k y_k\Big)=v_j \quad\checkmark
$$

即：

```python
gradients = torch.tensor([0.1, 1.0, 0.0001])
y.backward(gradients)
```

数学上完全等价于先构造 `out = 0.1*y[0] + 1.0*y[1] + 0.0001*y[2]`，再对 `out` 调用 `.backward()`。这也是为什么 `y` 是标量时可以不传参数：默认 `gradients=torch.tensor(1.)`，隐含 `out := y` 本身，自然 $\partial\text{out}/\partial y=1$。

### gradients 的形状约束——唯一的硬性约束

前面推导过 $v_j = \partial\text{out}/\partial y_j$——$v$ 是"对 $y$ 每个分量的梯度"，所以**形状必须和 $y$ 完全一致**，和 $x$ 的形状没有任何关系。这是调用 `y.backward(gradients)` 时唯一真正会报错的硬性约束——数值大小、正负、是不是"合理的归一化结果"都没有限制，只有**形状必须和 y 对齐**这一条是刚性的。

推广到二维张量看得更清楚。假设 $x$ 是形状 $(m, n)$ 的二维张量，$y = f(x)$ 是形状 $(n, k)$ 的二维张量（$f$ 把 $x$ 映射成另一种形状，具体是什么运算不重要）：

$$
x \in \mathbb{R}^{m\times n} \xrightarrow{\ f\ } y \in \mathbb{R}^{n\times k}
$$

那么 `gradients` 的形状必须是：

$$
\text{gradients.shape} = y.\text{shape} = (n,\ k)
$$

**和 $x$ 的形状 $(m,n)$ 完全无关**——即使 $m$、$k$ 数值上和 $n$ 相等或不等，`gradients` 也只看 $y$ 的形状，不看 $x$ 的形状。而 `backward()` 算出来的 `x.grad`，形状则永远和 $x$ 保持一致，即 $(m, n)$。

```python
x = torch.randn(m, n, requires_grad=True)   # x: (m, n)
y = f(x)                                     # y: (n, k)，具体运算视 f 而定

gradients = torch.randn(n, k)                # 必须和 y 同形状 (n, k)，与 x 的 (m, n) 无关
y.backward(gradients)

print(x.grad.shape)   # torch.Size([m, n])  —— 和 x 同形状
```

一句话记忆：**`gradients` 永远和 `y` 同形状，`x.grad` 永远和 `x` 同形状；两者形状可以完全不同，中间靠雅可比矩阵 $J$（逻辑形状 $y.\text{numel()} \times x.\text{numel()}$）连接起来。**

### 链条再长也一样：在哪个张量上调用 backward，gradients 就必须和它同形状

上面的约束只讨论了一步 $x \to y$，但实际代码里常常是更长的链条，比如 $x \to y \to z \to z_1$（每一步都是某种运算）：

```python
x = torch.randn(m, n, requires_grad=True)
y = f1(x)     # y 的形状随 f1 而定
z = f2(y)     # z 的形状随 f2 而定
z1 = f3(z)    # z1 的形状随 f3 而定
```

这时候如果调用 `z1.backward(gradients)`，规则完全不变，只是"对象"换成了 `z1`：

<p><span style="color:red"><b>不管中间经过了多少层运算，gradients 只需要和"你调用 .backward() 的那个张量"形状一致——这里就是 z1，跟 x、y、z 的形状统统无关。</b></span></p>

```python
gradients = torch.randn(*z1.shape)   # 只需要和 z1 同形状，与 x/y/z 的形状都无关
z1.backward(gradients)

print(x.grad.shape)   # 自动等于 x.shape，不管中间经过了多少层
```

原因还是同一套推导：`gradients` 的语义是 $v=\partial\text{out}/\partial z_1$，它描述的是"假设的下游 out 对 $z_1$ 的敏感度"，天然只和 $z_1$ 的形状绑定。调用之后，autograd 沿着计算图**反向走完整条链**，每一步都是局部 VJP，逐层向前传：

$$
v \;\xrightarrow{J_{z_1\to z}^T}\; \frac{\partial\,\text{out}}{\partial z} \;\xrightarrow{J_{z\to y}^T}\; \frac{\partial\,\text{out}}{\partial y} \;\xrightarrow{J_{y\to x}^T}\; \frac{\partial\,\text{out}}{\partial x} = x.\text{grad}
$$

一直传到所有 `requires_grad=True` 的叶子节点为止；`y`、`z` 如果没有 `retain_grad()`，它们的 `.grad` 依然是 `None`——链条长度只影响反向传播要走几步，不影响 gradients 的形状规则。

### v 不是 y 的数值——常见误解辨析

$v$（也就是 `gradients`）的形状和 $y$ 一样，容易被误认为是 $y$ 经过某种归一化/求和得到的结果，比如 `.sum()` 或 `.norm()`。实际验证一下并不成立：

| 假设的 out | 对应的 v = ∂out/∂y | 和例子里的 [0.1, 1.0, 0.0001] 是否吻合 |
|---|---|---|
| `out = y.sum()` | $v=[1,1,1]$（全1） | 否 |
| `out = y.norm()`（L2范数） | $v = y/\lVert y\rVert_2$（$y$ 的单位向量，这才是真正的"归一化"） | 否（本例中约为 $[0.271, 0.047, 0.953]$） |
| 本例中的 `gradients` | 外部凭空指定，不对应任何具体的 out | —— |

结论：`[0.1, 1.0, 0.0001]` 只是教程作者随手指定的演示权重，跟 $y$ 的取值、跟 `.sum()`/`.norm()` 这类运算都没有关系——$v$ 可以是任意与 $y$ 同形状的向量，autograd 只管照着算 $J^Tv$，不会检查它是否"从 $y$ 计算而来"。

一个直接的反证：把 $y$ 的值原封不动，只换 `gradients`，`x.grad` 会剧烈变化——说明 $y$ 的实际数值根本没参与 $J^Tv$ 这一步的输入（本例中 $J=2^kI$ 只跟"乘了几次2"有关，和 $x,y$ 具体数值无关，因为是线性变换）：

```python
y.backward(torch.tensor([1.0, 0.0, 0.0]))
print(x.grad)   # tensor([512., 0., 0.])
```

### y.grad 是不是就是 v

分两种情况，取决于 `y` 是不是叶子节点（leaf tensor）：

- 本例中的 `y` 是 `x` 经过多次乘法算出来的**非叶子张量**，PyTorch 默认**不会**给非叶子张量保存 `.grad`（省内存），所以默认情况下 `y.grad` 是 `None`。
- 若显式调用 `y.retain_grad()` 再执行 `y.backward(gradients)`，`y.grad` 会**恰好等于传入的 `gradients`**——因为 `.grad` 存的语义永远是"out 对这个张量的梯度"，而 `gradients` 定义上就是 $\partial\text{out}/\partial y$，两者本就是同一个量的两种称呼。

```python
x = torch.randn(3, requires_grad=True)
y = x * 2
while y.data.norm() < 1000:
    y = y * 2

y.retain_grad()                     # 让非叶子节点也保留梯度
gradients = torch.tensor([0.1, 1.0, 0.0001])
y.backward(gradients)

print(y.grad)   # tensor([0.1000, 1.0000, 0.0001])  —— 和 gradients 完全一样
print(x.grad)   # tensor([5.1200e+01, 5.1200e+02, 5.1200e-02])
```

### 用 `torch.no_grad()` 暂停梯度追踪

如果 `.requires_grad=True` 但又不希望某段代码被 autograd 追踪（比如推理阶段不需要反向传播），可以用 `with torch.no_grad():` 包裹：

```python
print(x.requires_grad)          # True
print((x ** 2).requires_grad)   # True，运算结果也会被追踪

with torch.no_grad():
    print((x ** 2).requires_grad)  # False
```

在 `no_grad()` 代码块里，新产生的张量不会记录 `grad_fn`，即不会被纳入反向传播的计算图，可以节省显存、加快计算——这也是模型评估/推理阶段的常见写法。

## 词源小知识

"norm" 来自拉丁语 **norma**（标准、规范、直角尺），数学中借用表示"衡量向量大小的标准化定义"。归一化 **normalize** 就是这个词的动词形式——把向量除以自己的范数，变成"标准长度（1）"的向量。

## 附录：`norm(p=float('inf'))` 里用到的 Python 特殊值

计算 L∞ 范数时用到了 `float('inf')`，顺带记录一下 Python 里类似的"特殊值"都有哪些。

### 1. IEEE 754 浮点数的特殊值（`float` 类型专属）

| 特殊值 | 写法 | 含义 |
|---|---|---|
| 正无穷 | `float('inf')` 或 `math.inf` | 比任何有限数都大 |
| 负无穷 | `float('-inf')` 或 `-math.inf` | 比任何有限数都小 |
| NaN（非数） | `float('nan')` 或 `math.nan` | 未定义运算结果，如 `0/0`、`inf - inf` |
| 正零 | `0.0` | 一般意义上的0 |
| 负零 | `-0.0` | 数值上等于0.0，但符号位不同（IEEE754底层区分） |

严格来说只有 **3 种"非正常数值"**：`inf`、`-inf`、`nan`，这是 IEEE 754 标准强制要求任何浮点数实现都要支持的。

### 2. Python 语言层面的内置常量（Built-in Constants）

Python 官方文档 "Built-in Constants" 里列出的、语言级别的特殊常量，一共 **6 个**：

| 值 | 类型 | 含义 |
|---|---|---|
| `True` | `bool` | 布尔真值，本质是 `int` 的子类（`True == 1`） |
| `False` | `bool` | 布尔假值，本质是 `int` 的子类（`False == 0`） |
| `None` | `NoneType` | 表示"没有值"，全局唯一，只有一个实例 |
| `NotImplemented` | `NotImplementedType` | 运算符重载（如 `__eq__`、`__add__`）中表示"这个操作没实现，请对方或Python尝试别的方式" |
| `Ellipsis`（即 `...`） | `EllipsisType` | 常用于类型标注占位、NumPy/PyTorch 多维切片（如 `x[..., 0]`） |
| `__debug__` | `bool` | 正常运行时是 `True`；用 `python -O` 优化模式启动时是 `False`，此时 `assert` 语句会被跳过 |

其中 `True`、`False`、`None`、`NotImplemented`、`Ellipsis` 都是**单例（singleton）**——整个 Python 进程里各自只存在一个实例，所以判断时惯例用 `is`（比如 `x is None`），而不是 `==`。

### 3. 数值边界常量（不算"特殊值"，但常一起用到）

这些不是"特殊值"本身，而是描述数值系统边界的**普通数字**，容易和上面的特殊值混着用：

| 值 | 来源 | 含义 |
|---|---|---|
| `math.pi` | `math` 模块 | 圆周率 π |
| `math.e` | `math` 模块 | 自然常数 e |
| `math.tau` | `math` 模块 | 2π |
| `sys.maxsize` | `sys` 模块 | 平台上 `Py_ssize_t` 能表示的最大值（约等于 int 索引上限，不是"整数最大值"，Python int 本身无上限） |
| `sys.float_info.max` | `sys` 模块 | 浮点数能表示的最大有限值，超过就变成 `inf` |
| `sys.float_info.min` | `sys` 模块 | 浮点数能表示的最小正规数 |

import math
